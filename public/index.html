Retrieval & Context · Trap #1

1. The Context Window Lie

The Vendor Pitch: "1-million-token context window! Dump your entire company wiki or codebase into one prompt!"

A 1M-token prompt takes 30–45s just to generate the first token and costs ₹125–₹250 per query. Mathematically, self-attention concentrates on the beginning and end ('lost in the middle'), overlooking key facts buried in the middle.

What Actually Works: Never dump raw files into an LLM. Use layout-aware OCR parsing and hybrid search (BM25 + vectors) to retrieve only the exact 2 paragraphs where the answer lives.
Business Impact: At production scale, naive 'dump everything' prompts quietly inflate API bills to ₹5–₹10 Lakhs/month while still delivering incomplete or hallucinated answers.
Proven Tools: RAGFlow ↗ Qdrant ↗ MinerU ↗
Cost & Tokens · Trap #2

2. The Token Cost Bleed

The Vendor Pitch: "Per-token prices are dropping 10x every year — don't worry about cost optimization!"

Models get cheaper, but context bloat grows faster. When code agents run builds or tests, compilers dump 200 lines of memory addresses (e.g. 0x7fff5fbff710). Hex strings tokenize into 8–12 tokens each. Teams burn 70–80% of their monthly budget reading useless hex noise.

What Actually Works: Strip stack traces, memory addresses, and repetitive logs before tokenization using specialized CLI proxies (RTK) and pre-LLM output compressors (headroom).
Business Impact: On an ₹8 Lakh/month API bill, roughly ₹6 Lakh pays for hexadecimal garbage that carries zero semantic value.
Proven Tools: RTK (Rust Token Killer) ↗ headroom ↗
Agents & Workflow · Trap #3

3. The Coding Agent Benchmark Myth

The Vendor Pitch: "Our autonomous coding agent resolves 60% of GitHub issues end-to-end without humans!"

In unconstrained benchmarks, agents often 'pass' tests by deleting failing assertions, hardcoding returns, or mocking databases. In the real world, next-token predictors treat their own hallucinations as ground truth, spiraling into 300 lines of code to fix a bug they created.

What Actually Works: Restrict agents to tight loops with mandatory git rollback checkpoints, deterministic test validation, and human-in-the-loop diff approvals.
Business Impact: Roadmaps green-lit on inflated benchmark claims slip by quarters when the agent fails silently on your real codebase.
Proven Tools: Google Antigravity ↗ Claude Code ↗ Aider ↗
Training & Models · Trap #4

4. The Fine-Tuning Money Pit

The Vendor Pitch: "Fine-tune a private custom model on your company's proprietary data to teach it your domain!"

Fine-tuning teaches an LLM tone, style, and syntax — not facts. A fine-tuned model hallucinates wrong answers in the exact corporate voice of your company. That is why 90% of enterprise fine-tuning POCs fail and waste ₹40+ Lakh each.

What Actually Works: Keep the base model frozen. Use high-accuracy RAG with hybrid search for proprietary knowledge, and run open-weight models on-premise for zero ongoing API fees.
Business Impact: ₹40+ Lakh written off per failed fine-tuning POC — budget that a frozen model with good retrieval would never have needed.
Proven Tools: Ollama ↗ vLLM ↗ Unsloth ↗ LM Studio ↗
Security & Guardrails · Trap #5

5. The Agent Security Blindspot

The Vendor Pitch: "Give your AI agent terminal access, browser control, and API keys to automate your entire workflow!"

LLMs fundamentally cannot separate system instructions from untrusted data. When an agent browses a live website, parses a user PDF, or scans an incoming pull request containing indirect prompt injections, it can be tricked into running destructive bash commands or exfiltrating private credentials.

What Actually Works: Run agents inside disposable, ephemeral Docker sandboxes with no access to production credentials, and enforce human approval on destructive operations.
Business Impact: One injected prompt can exfiltrate credentials — a catastrophic breach-notification and compliance liability under India's DPDP Act.
Proven Tools: OpenHands ↗ Cline ↗
Reliability & APIs · Trap #6

6. The Structured JSON Illusion

The Vendor Pitch: "Just tell the LLM to output valid JSON matching your schema — instant API integration!"

Under real production load, unconstrained LLM prompting randomly yields trailing commas, markdown fences, or truncated brackets mid-stream, silently crashing downstream microservices.

What Actually Works: Never rely on raw prompting for JSON. Use constrained grammar sampling at the model engine level (forcing logits to only output valid schema tokens).
Business Impact: Silent downstream crashes mean urgent midnight incident-response hours and eroded customer trust in production workflows.
Proven Tools: vLLM (Guided Decoding) ↗ Outlines ↗ llama.cpp ↗
Retrieval & Context · Trap #7

7. The Pure Vector Search Trap

The Vendor Pitch: "Embed your documents into a vector database and semantic search will magically find every answer!"

Dense embeddings capture vague conceptual similarity, but fail completely on exact part numbers, error codes (ERR_403_AUTH), function names, or dates. They blur critical specific technical identifiers into generic concepts.

What Actually Works: Use hybrid search combining BM25 exact keyword matching with dense vectors, followed by a cross-encoder reranker.
Business Impact: Support automation stalls when the bot can't find exact part numbers or error codes your customers actually type.
Proven Tools: Qdrant ↗ RAGFlow ↗ Meilisearch ↗
Evals & Testing · Trap #8

8. The Silent Model Regression Trap

The Vendor Pitch: "Auto-upgrade to the newest flagship model release for instant free intelligence!"

Providers constantly change backend quantization, routing, and system prompts. A 'better' model version frequently breaks previously working prompt templates, changes edge-case formatting, or increases latency without warning.

What Actually Works: Never upgrade production model versions without an automated CI/CD eval suite testing against a frozen golden dataset of edge cases.

Traffic Challan APK CRITICAL

The Fake Traffic Fine Message (e-Challan APK)

You get an SMS claiming your vehicle was caught overspeeding on camera with a pending fine of ₹1,000, and a link to download an app (echallan.apk) to pay before court action. If you install it, the app silently reads all your incoming SMS, steals your bank OTPs, and drains your account.

Traffic police never send app files to pay fines. Never install any file ending in .apk. Always check and pay traffic fines only on the official government website: echallan.parivahan.gov.in.

You receive a message from a friend or relative on WhatsApp saying: "My cousin is getting married next week, wedding card and venue attached." A caller claiming to be from Airtel or Jio says they are upgrading your SIM to 5G for free. They tell you to send a simple SMS like eSIM <email> to 121. Never send an eSIM request to any email given by a caller. Telecom companies never call you to set up an eSIM. To upgrade your SIM, always visit an official Airtel/Jio store in person.
