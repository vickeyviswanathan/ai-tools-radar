Retrieval & Context · Trap #1

1. The Context Window Lie

The Vendor Pitch: "1-million-token context window! Dump your entire company wiki or codebase into one prompt!"

Loss-in-the-middle degradation causes LLMs to ignore needle-in-the-haystack facts once context exceeds 32K tokens. High Time-To-First-Token (TTFT) and linear token costs make unindexed raw-file prompting unusable in production.

What Actually Works: Never dump raw unindexed documents into an LLM prompt. Use prompt compression to discard low-entropy tokens and targeted cross-encoder rerankers on small, precise retrieved chunks.
Business Impact: Legal queries hallucinate terms found in middle sections; enterprise support bots cost 20x more while delivering worse answers.
Proven Tools: LLMLingua ↗ FlashRank ↗ Qdrant ↗
Cost & Tokens · Trap #2

2. The Token Cost Bleed

The Vendor Pitch: "Per-token prices are dropping 10x every year — don't worry about cost optimization!"

Agentic tool runs, compiler output dumps, and large git diffs consume millions of tokens in minutes. Automated CI/CD agents burn budgets on whitespace and noisy terminal logs.

What Actually Works: Strip stack traces, memory addresses, and repetitive logs before tokenization using specialized CLI proxies (RTK) and pre-LLM output compressors (headroom).
Business Impact: A rogue coding agent loops overnight on a build failure and consumes ₹1,50,000 in API tokens on a single pull request.
Proven Tools: RTK (Rust Token Killer) ↗ headroom ↗
Agents & Workflow · Trap #3

3. The Coding Agent Benchmark Myth

The Vendor Pitch: "Our autonomous coding agent resolves 60% of GitHub issues end-to-end without humans!"

High benchmark scores test synthetic micro-tasks on cherry-picked repositories. In real messy codebases, unsupervised agents invent fake dependencies, delete critical tests, or claim a bug is fixed by deleting the failing test suite.

What Actually Works: Restrict agents to tight loops with mandatory git rollback checkpoints, deterministic test validation, and human-in-the-loop diff approvals.
Business Impact: Unreviewed agent merges introduce security vulnerabilities or delete business logic, requiring days of rollback firefighting.
Proven Tools: Google Antigravity ↗ Claude Code ↗ Aider ↗
Training & Models · Trap #4

4. The Fine-Tuning Money Pit

The Vendor Pitch: "Fine-tune a private custom model on your company's proprietary data to teach it your domain!"

Fine-tuning adjusts style, tone, and grammar format — it does NOT reliably store retrievable factual knowledge. It induces catastrophic forgetting of base capabilities while rapidly growing stale when company documents update.

What Actually Works: Keep the base model frozen. Use high-accuracy RAG with hybrid search for proprietary knowledge, and run open-weight models on-premise for zero ongoing API fees.
Business Impact: Companies spend ₹25,00,000 on GPU cluster compute to fine-tune a model that hallucinates worse than off-the-shelf models with clean retrieval.
Proven Tools: Unsloth ↗ vLLM ↗ Ollama ↗
Security & Guardrails · Trap #5

5. The Agent Security Blindspot

The Vendor Pitch: "Give your AI agent terminal access, browser control, and API keys to automate your entire workflow!"

An LLM interpreting external web pages or untrusted user inputs can be hijacked via indirect prompt injection to execute `rm -rf`, clone malicious packages, or curl environment secrets to external attacker servers.

What Actually Works: Run agents inside disposable, ephemeral Docker sandboxes with no access to production credentials, and enforce human approval on destructive operations.
Business Impact: An agent instructed to 'fix a bug from a GitHub issue' reads an injected prompt in an issue comment and exfiltrates `.env` AWS keys.
Proven Tools: OpenHands ↗ Cline ↗
Reliability & APIs · Trap #6

6. The Structured JSON Illusion

The Vendor Pitch: "Just tell the LLM to output valid JSON matching your schema — instant API integration!"

Under latency pressure or novel input tokens, LLMs will prepend conversational preamble, output trailing commas, or truncate JSON arrays when nearing token limits, breaking downstream backend parsers.

What Actually Works: Never rely on raw prompting for JSON. Use constrained grammar sampling at the model engine level (forcing logits to only output valid schema tokens).
Business Impact: Downstream checkout or database ingestion services crash silently in production due to an unescaped double-quote or missing closing brace.
Proven Tools: vLLM (Guided Decoding) ↗ Outlines ↗ llama.cpp ↗
Retrieval & Context · Trap #7

7. The Pure Vector Search Trap

The Vendor Pitch: "Embed your documents into a vector database and semantic search will magically find every answer!"

Dense embeddings compress semantic meaning into float vectors, entirely erasing exact matches for error codes, part numbers, stock tickers, and proper names where semantic proximity is useless.

What Actually Works: Use hybrid search combining BM25 exact keyword matching with dense vectors, followed by a cross-encoder reranker.
Business Impact: Customer support RAG answers product support questions with solutions for entirely different model numbers because their embeddings were close.
Proven Tools: Qdrant ↗ RAGFlow ↗ Meilisearch ↗
Evals & Testing · Trap #8

8. The Silent Model Regression Trap

The Vendor Pitch: "Auto-upgrade to the newest flagship model release for instant free intelligence!"

New model checkpoints regularly regress on edge cases: system prompt adherence shifts, refusal behaviors change, and structured output formatting alters slightly, breaking brittle production parsers.

What Actually Works: Never upgrade production model versions without an automated CI/CD eval suite testing against a frozen golden dataset of edge cases.
Business Impact: A point-release update causes a 12% jump in user-facing refusals on benign customer queries.
Proven Tools: Promptfoo ↗ DeepEval ↗ Giskard ↗
Agents & Workflow · Trap #9

9. The Multi-Agent Runaway Loop Trap

The Vendor Pitch: "Deploy autonomous swarms of agents that critique and coordinate with each other 24/7!"

Autonomous agent swarms rapidly descend into recursive critique loops, infinite agreement deadlocks, or hallucination cascades. Without strict iteration counters and cycle detection, two agents can burn through thousands of dollars in minutes.

What Actually Works: Enforce strict hard-stop turn budgets (max 5-8 iterations), acyclic execution graphs (DAGs), and deterministic exit criteria for all subagents.
Business Impact: Unbounded multi-agent swarms can rack up a ₹2,00,000+ cloud bill in a single afternoon with zero completed tasks.
Proven Tools: n8n ↗ Dify ↗ Langflow ↗
Retrieval & Context · Trap #10

10. The PDF & Table Chunking Shredder

The Vendor Pitch: "Simple character or sentence RAG chunking easily handles enterprise PDFs and balance sheets!"

Standard text chunkers slice documents at arbitrary token limits, severing table rows from headers. Financial figures end up mapped to wrong columns, causing RAG models to confidently invert financial reports and legal contract numbers.

What Actually Works: Replace text-based chunking with layout-aware vision-OCR parsers that reconstruct multi-column layouts and tables into structured Markdown tables prior to vector embedding.
Business Impact: Executives make multi-crore investment decisions based on corrupted balance-sheet numbers generated by naive RAG chunkers.
Proven Tools: MinerU ↗ PyMuPDF4LLM ↗ pdf oxide ↗
Serving & Infra · Trap #11

11. The TTFT & Latency Wall

The Vendor Pitch: "Deep reasoning models give flawless output — users won't mind waiting 30 seconds!"

In real interactive customer-facing interfaces, any response taking over 2 seconds causes immediate drop-off and cart abandonment, regardless of how smart the model is.

What Actually Works: Implement tiered speculative routing: use ultra-fast sub-100ms small models for initial responses, and escalate to reasoning engines asynchronously in the background.
Business Impact: Users abandon an AI workflow because the 30-second reasoning latency feels unresponsive compared to instant search.
Proven Tools: vLLM ↗ Groq ↗ OmniRoute ↗
Evals & Testing · Trap #12
